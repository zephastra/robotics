# 手动输入修复 · 2026-09-07

## 使用

```bash
cd ~/projects/004_humanoid_locomotion
bash run_demo.sh --robot t800 --mode manual
```

关闭旧进程后重新启动。请让 **`004 Controls - EngineAI T800` 控制窗口**获得焦点，等待 2 秒仿真时间，再按住 W 或鼠标按住 Forward 按钮。G1 使用相同操作方式。

- W/S 前后；A/D 转向；Q/E 侧移；R/T 弧线前进；也支持 W+A/W+D 组合。
- 松键、鼠标移出方向按钮、切换到其他窗口：撤销移动指令并减速保持，不锁定坐标。
- X/空格：停止；P：暂停/恢复；F：推力实验；C：取消并进行停车验收。
- 停止/暂停后需松开旧按键再重新按下，防止旧命令自动恢复。若松键发生在其他窗口，回到控制窗口后可能需要先按下再松开一次来解除该键的防误恢复锁定。
- 关闭控制窗口：受控取消；关闭 MuJoCo 窗口或 Ctrl+C：直接结束仿真，两者不同。
- 终端/MuJoCo 窗口不再接受手动移动键，只保留 C/X。不要在仿真窗口按空格当作控制面板的 Stop，它有自己的原生快捷键。

## 修复原因

原实现将一次按键事件转换为 0.5 秒墙钟有效的指令，误把系统连发当成可靠的按住检测。慢仿真下，0.5 秒墙钟只对应很短的物理积分时间，指令尚未充分加速便失效。MuJoCo 的按键回调也不提供可靠的持续按住/松开接口。

另外，旧终端解析器逐字节解释输入，方向键序列 `ESC [ C` 会被当作取消。现在过滤 CSI/SS3、OSC/DCS 和带括号粘贴序列。控制面板忽略 Ctrl/Alt 快捷键，避免复制等操作触发移动或取消。

## 验证方式与边界

- 53 项自动检查通过：原有测试、ANSI 字节解析、心跳过期、暂停/取消抑制移动、5 项实际 Tk 图形事件测试，以及 2 项禁止调用阻塞文字叠加接口的回归测试。
- 图形测试覆盖单次 W 按下跨越旧超时、松开、鼠标释放、失去焦点、自动重复不重复切换暂停、关闭时取消、Ctrl+C/方向键不误取消。
- `scripts/verify_manual.py` 在实际应用循环中注入一次 Tk W 按下，保持 5 秒仿真时间后松开，再触发取消；检查持续输入、实际前进及停车验收。不是仅绕过输入层直接给策略速度。
- 自动输入测试使用私有 Xvfb 显示，避免与用户桌面按键/焦点竞争；测试依赖只解包到本工程 `.cache/gui-test-runtime/`，不安装系统包。此目录不属于日常运行依赖。
- 第一次桌面集成测试被焦点切换打断并记录失败；私有显示的后续测试用于排除输入干扰。失败报告保留，未改成成功。
- 这是程序生成的 Tk 图形事件 + 实际机器人仿真测试，**不是人工在用户键盘上的验收**。请按上面的步骤进行最终手动确认。

## 2026-09-07：双窗口无响应修复

用户实际桌面运行中，控制面板和 MuJoCo 原生控件均出现无响应。对运行进程多次读取调用栈，主线程持续停在 `add_markers() -> viewer.set_texts()`，原生栈显示该调用内部等待；并非仅 W 键未被识别。内部锁等待的完整成因尚未验证。

现在移除仿真循环中的 `viewer.set_texts()` 调用，不再显示自定义文字叠加层；目标标记与相机跟踪保留。手动状态、仿真时间及速度仍显示在独立控制面板，终端保留阶段日志。没有修改 MuJoCo 安装、机器人模型或策略参数。

此前的私有显示自动测试未捕获这个真实桌面故障，因此不能把自动测试通过等同于人工输入验收。修复后仍需在 WSLg 桌面检查原生控件响应及控制面板的按住、松开行为。
