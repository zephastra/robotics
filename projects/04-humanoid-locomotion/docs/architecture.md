# 控制与验证架构

## 三个控制层

1. 任务/交互层：理想定位下的目标点反馈或带超时的人工速度指令；输出机体坐标速度。
2. 步态策略层：G1 为 50 Hz / 47 维输入 / 12 维动作；T800 为 100 Hz / 1083 维历史输入 / 22 维动作。分别加载对应上游策略。
3. 关节/物理层：500 Hz，PD 计算关节力矩，MuJoCo 按上游模型的关节力矩限制与接触进行积分。

G1 观测包含角速度、重力投影、速度指令、相对关节位置、关节速度、上次动作和步态相位。T800 使用历史观测，不含 G1 的步态相位；详见 [双模型适配](robots.md)。不是将人体关节关键帧直接播放为动画。

启动时检查模型自由基座、关节数量/顺序、资源哈希和控制周期。初始化位姿只在第一步物理积分前设置；运行中不通过赋值 qpos/qvel 实现移动或恢复。

## 真值与适用范围

任务层与位置保持直接读取仿真底座 xy/yaw；步态观测也使用理想模拟状态。报告明确标记此边界。这验证的是控制逻辑在理想状态反馈下的表现，不是状态估计器性能。

场景没有规划器或障碍物感知。远离目标时先朝向目标，再向前走；近距离使用机体系 x/y 误差和目标朝向反馈。位置/朝向连续合格且保持期平均平面速度不超限才接受该目标。

## 动态保持与取消

原始零速度策略会漂移，因此 `stand`、`manual` 松键、目标保持使用位置反馈。保持时允许脚小幅移动，报告足部高度变化；不称为静态站立。

`C` 取消后先将速度指令平滑降到零，3 秒后记录保持点，随后进行 10 秒位置保持验收。失败会返回 `FAILED`，不能只因为指令为零就报告停车成功。保持阶段依赖理想定位。不同模式的 `X/Space` 仅表示手动停止；自动任务必须用 `C` 取消。

关闭 MuJoCo 窗口/Ctrl+C 直接结束仿真，不把这类退出记录成经过验收的停车。关闭独立的 `004 Controls` 窗口则撤销移动指令并请求受控取消，仿真继续完成停车验收。`P` 暂停的是模拟时间，解除暂停前使键盘指令过期；取消会解除暂停以避免无法完成停车。不是物理急停。

手动模式使用独立 Tk 窗口处理 KeyPress/KeyRelease、鼠标松开与失去焦点；20 ms 心跳维持按住状态，0.5 秒看门狗防止界面卡住后继续行走。不依赖 MuJoCo viewer 的单次按键回调推断“持续按住”。终端仅提供 C/X，ANSI 转义与带括号粘贴内容会被过滤。详见 [手动控制修复](manual-controls.md)。

## 扰动与异常

推力通过骨盆的 `xfrc_applied` 在世界坐标施加，默认沿 +Y、持续 0.2 秒；记录 N、秒和冲量 N·s，不修改根部坐标。人体的时相、方向和外力作用位置都会影响结果。

骨盆过低或躯干倾角过大持续超过去抖时间，判定跌倒并终止试验。数值异常、仿真时间外部重置、模型/策略不匹配、目标超时均产生失败记录。强扰动导致失败是有效实验数据，不应删除或放宽阈值掩盖。

## 独立性与图形

不导入 rclpy、Gazebo 或 Unitree 实物 SDK，没有面向硬件的网络控制通道。模型与权重下载完成后，日常运行不需要联网。安装环境位于本工程 `.venv`，不会 source 历史工程。

WSL 本机默认 OpenGL 渲染器是 llvmpipe。启动器为当前进程选择现有 D3D12 驱动以使用独显；可通过环境变量选择软件渲染。不更改系统库、驱动、登录脚本或其他项目环境。
