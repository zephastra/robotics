# 实现与边界

## 控制链路

任务执行器 → Nav2 导航 Action → `/nav_cmd_vel` → 独立速度联锁 → `/cmd_vel` → Gazebo 差速底盘。

相机 RGB + CameraInfo → 颜色连通域 → 已知桌面平面反投影 → `base_link` 下的抓放坐标 → SCARA 逆运动学 → 关节控制器 → JointState 反馈。

升降轴使用力 PID 和名义重力补偿；其余操作关节使用 Gazebo 理想速度伺服逼近位置目标。不是工业伺服电机模型。机械臂动作始终在底盘停止后执行，行驶前必须收拢。

## 坐标系

`map → odom` 由 AMCL 发布；`odom → base_link` 来自 Gazebo 差速里程计；机器人内部 TF 由本工程 URDF 和 JointState 发布。没有读取 Gazebo 底盘真实坐标后直接冒充定位。

激光链路是 Gazebo → `/scan_raw` → 本体遮挡过滤 → `/scan`。相机立柱、升降柱和处于扫描高度的夹爪掌部回波会按本工程几何尺寸过滤。被遮挡的射线标记为 NaN，不会把立柱背后未经观测的区域当作空闲空间。改变这些结构或雷达安装位置后必须同步调整过滤几何。

轮轴速度上限与机械臂独立：轮轴为 8 rad/s，导航期望线速度为 0.25 m/s；机械臂保持低速。轮轴上限只是模型能力边界，不表示导航会以该上限行驶。

RGB 相机固定在底盘 `(0.30, 0, 1.80)`，垂直向下；图像向右对应底盘 `-Y`，向下对应 `-X`。用内参反投影到已知水平平面，因此目前不支持倾斜台面、不确定高度或倾斜物体。

## 返航精对位

起点前方 0.70 米处有紫红色矩形标记。相机根据连通域中心估计相对位置，根据长轴估计相对方向。任务把这个测量误差通过当前 TF 转换成小幅导航修正目标，最多修正三次，每次重新观察。相机误差达到要求后，才进行独立的仿真真实位置验收。

这解决的是导航到站之后的最后一段对位，不宣称单靠 AMCL 已达到相同的物理精度。标记方向有 180° 歧义，工作范围限定在粗导航已大致对准起点的情况下。修改起点时，必须同步移动场景中的标记和修改它相对理想底盘位置的偏移。

## 抓取与验收

`GuardedGrasp` 是明确标识的辅助抓取插件：

1. 默认没有物体附着。
2. 只有物体中心距夹爪参考点不超过 4.5 厘米、手指闭合、底盘停止，才创建固定刚体约束。
3. 释放操作删除约束，物体受重力和场景接触影响。
4. 托盘运输有独立的近距离固定/解锁操作；只有货物已在托盘附近才能固定。

插件的仿真位姿遥测用于验证抓起、托盘装载、运输、放置和返回；不能把这种验收能力当成真实机器人已经具备的传感能力。实物需要夹持检测、标定、真实碰撞模型、急停与安全控制。

## 故障处理

- 识别不到/识别到多个目标：停止，不沿用世界真值或写死位置补抓。
- 超出机械臂工作空间：拒绝执行。
- 关节、导航、相机启动或任务总时间超限：失败报告并停止底盘。
- 取消任务：请求取消导航，底盘停止，保留当前货物附着状态。
- 任务进程退出/心跳失联：独立联锁输出零速度。

当前故障策略是安全停止和可诊断报告，不承诺自动恢复所有异常；这是与全功能生产系统的明确差距。

## 独立性

所有模型、场景、地图、启动、导航参数、算法和测试位于本工程内部。只有 ROS 2、Nav2、Gazebo 等系统依赖。运行时不需要打开、source、复制或启动 001/002。
