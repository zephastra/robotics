# 自动操作站位：第一里程碑

本轮只实现接触诊断、候选操作站位和接近减速；不包含动态障碍绕行、任意朝向抓取或任务中目标跟踪。
当前仍在物理回归调试中，尚未作为验收通过的发布版交付。旧模式仅可用于对照，不保证无碰撞。
修改前版本保存在 WSL `~/projects/releases/007-pre-stance-20260909.tar.gz`，不要覆盖解压到当前工程。

## 运行

```bash
cd ~/projects/007_humanoid_visual_transport
bash run_demo.sh --stance auto --mode transport --keep-open
# 仅用于前后对照，旧流程并不保证无碰撞
bash run_demo.sh --stance legacy --mode transport --keep-open
.venv/bin/python -m pytest -q
.venv/bin/python scripts/batch.py --stance auto --seed 7 --workers 4
```

默认 `--stance auto`。沿用原有启动命令也会使用自动站位。单次报告保存在打印的 Report 目录，
批次汇总保存在 `reports/batch-<UTC时间>/summary.json`；失败不会被成功重跑覆盖。

## 已实现的决策

- 根据视觉箱体位置生成前方 0.24、0.28、0.32、0.36 m 与横向 0、±0.04 m 的候选站位；放置候选额外包含 0.40、0.44 m，仍必须通过 IK 与间距检查。
  当前站位在范围内时也参与评估；平移候选保留实测身体姿态，不会偷偷重置成零朝向，也不是全空间搜索。
- 通过双臂限位 IK 检查抓取、抬升，或放下、撤手的可达性。
- 在模型副本中采样检查手臂轨迹及手指闭合/释放，身体与已知工作台保持至少 25 mm、手部至少 3 mm 的规划间距。
- 可行候选按移动距离和身体间距评分；放置更偏重身体间距。没有可行候选就明确失败，不回退到未经检查的固定站位。
- 放置接近点在所选操作站位的桌外侧保留 0.08 m 余量；这是限定工作区的接近缓冲点，不是声称精确停在选定 IK 站位上。报告分别记录 `selected` 和 `approach_xy`，停稳后必须按实际姿态验算。
- 最终接近段加入速度反馈减速，进入 STOP 前验证低速，不再提前把规划目标覆盖成当前经过的位置。普通路段不提前限速，以免原步态在低指令区停滞。
- STOP 请求零速度；持续停稳后才建立静止保持参考。原规划目标保留，报告单独记录 `hold_anchor`，随后按实际站位重新验算。
- 到达后重新观察，并按实际机器人姿态复核放置动作；不合适时最多重新对齐两次。
- 重新选择放置站位时，使用视觉箱体位置和实际双手位置得到的抓持偏差，而不是重新假设理想对称抓持。
- 放置检查从当前手臂姿态开始下放，不要求经过执行器从未命令的额外抬高目标。释放时手臂缓慢向外、向上退出。
- 静止阶段底座偏离保持参考超过 0.12 m 会报告 `STATIONARY_BASE_DRIFT` 并结束仿真；这不是实机急停或平衡恢复。

`--hold-controller walking` 为默认；`--hold-controller posture` 是未验收的站立控制试验，
采用双脚承重后捕获关节姿态及渐变力矩控制，没有固定底座。多轮对照仍有对齐失败和
底座漂移，不能把它作为已解决静止平衡问题的方案，也不作为默认控制器。

`stance_plans` 保存候选、拒绝原因、选择结果和到达检查，便于解释为什么选择这个位置。

## 逆运动学和跟踪诊断

下放失稳复现中，右臂关节目标先出现大幅跳变，而限速后的关节跟踪误差较小。
求解器现在整体缩放增量，并对限位裁剪后的增量做回溯检查：只有末端位置误差下降才接受。
若限位阻挡阻尼最小二乘方向，则尝试投影梯度下降；两者均无法下降才保留当前解退出。
不会因为不可达目标而盲目累积使误差变大的步长。
这不保证目标可达，也不是全身平衡控制。
目前该求解保护只用于自动模式的下放、释放和撤手。抓取、抬升和旧模式保持原求解路径，
避免改变已验证的载物姿态。全局替换求解器曾导致四例均在 STOP 超时，已撤回全局启用。
放置候选检查也使用受保护求解；规划和执行均约束屈肘分支（肘俯仰不超过 -0.10 rad），
并把肘部旋转限制在本次抓持参考的 ±0.25 rad 内。这是当前搬运任务的软件姿态约束，
不修改模型物理限位，也不等于完整的手掌姿态规划。不可达仍需拒绝或重新对齐。

报告采样新增 `arm_solution`（任务求解目标）、`arm_command`（限速后的目标）、
`arm_joints`（实际关节位置）和 `arm_tracking_error`（最大绝对关节误差，rad），
用于区分求解跳变、限速滞后与执行跟踪失败。

## 接触诊断

`station_contact_diagnostics` 每个物理步检查机器人与工作台/标记支架的接触，记录各部位：

- 峰值法向接触力（N）；
- 接触持续时间（s，法向力超过 0.01 N）；
- 法向冲量（N·s）；
- 首次接触时间及任务阶段。

箱体放在桌面上的预期接触不计入这项机器人接触指标。`contact_free` 只代表这些已监测工作台
没有超过阈值的机器人接触，不等于整个世界无碰撞或真实硬件安全。
任务完成和接触结果分别报告；完成状态不因诊断记录被自动改写，也不能只看完成状态验收。

## 信息来源和限制

`config/workcell.json` 是已知固定取料台地图；接收台平移来自视觉标记，几何尺寸、朝向和标记偏置已知。
规划模型中的工作台位置由上述输入设置，不读取当前箱体真值。已有测试会扰动箱体仿真真值，
确认在视觉输入不变时，规划结果不变；规划也不能改变实际机器人状态或模型。

检查采用保守世界轴对齐包围盒分离下界和 MuJoCo 几何距离。
距离接口与凸几何碰撞管线的关系见 [MuJoCo 官方说明](https://mujoco.readthedocs.io/en/3.3.5/computation/#geom-distance)。
分离下界也用于防止数值零距离把明显分离的包围盒错误判为接触。

离散采样不是连续无碰撞证明；当前不验证全程载物包络、全身自碰撞、任意新障碍、步态平衡裕量，
也没有替换原有的限定工作区通路。规划可行必须继续通过真实物理运行验收。
源桌仍假设固定；移动源桌需要更新已知地图，不能只移动箱子后宣称支持场景整体变化。
