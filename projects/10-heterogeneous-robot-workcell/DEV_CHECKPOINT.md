## 恢复开发

1. 克隆仓库并检出 dev，将本目录作为独立工程目录使用。
2. 保留 `assets/`、`policies/`、`licenses/` 和全部相对路径，不依赖 001～009 的运行目录。
3. 按 `requirements-p1.txt`、`docs/ENVIRONMENT.md` 和实际源码核对并重建环境。ROS 组件与普通虚拟环境可能使用不同解释器。
4. 如遇 MNN 可执行栈问题，阅读 `experiments/fix_mnn_stack.py` 和相关环境记录；修改环境前先核对脚本，不依赖未上传的旧二进制。
5. 重新运行必要实验，并采用新的 run ID。历史报告引用不等于当前版本复现证据。

Windows 文件复制不保留 UNIX 执行位；用 `bash scripts/env.sh`（如需环境变量传入当前 shell 则 source）、项目 Python 或 ROS 系统 Python 按入口约定调用，恢复可执行位时检查具体脚本。历史执行位可查旧提交的清单。公开 README、许可总说明和字节属性与源端有发布差异，见 `DEV_PUBLICATION_OVERRIDES.json`。WSL 原文件没有被改写。
