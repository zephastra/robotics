# §23.3 变更前声明 — 监督时钟换域：墙钟 → sim 钟（2026-10-04，第 4 次变更）

## 1. 当前门
**G1** — 五个最小物理反例已全部能跑，但 `relblk` run（`p4-belt-g1-relblk-20261004T100633`）
暴露出**期限与几何的竞速**，该 run 作为"释放不能完成"的证据**无效**（证据目录保留不删）。

## 2. 失败的可观察原因
`relblk` trace：sim 6.82 闭合采样上 pos=−0.000636/−0.000656、双侧接触、力 ~1.04 N
——**几何已到位**；但契约先查墙钟期限（27.2 s），本次 run 主机慢（总墙钟 54.2 s，
pos3 仅 44.6 s），6.82 时墙钟已超限 ⇒ `CLOSE_TIMEOUT` 抢在几何之前开火。
契约测的是**主机快慢**，不是机构快慢。且无任何墙钟系数能同时满足
"覆盖主机最慢节奏"与"小于整场 run 墙钟"两个约束（实测比率 2～5 波动）——
墙钟尺在本环境**结构性不可用**。教训 #9：换尺，不是调阈值。

## 3. 这次只改变的一个因素
**监督时钟域：探针把 `data.time`（sim 秒）作为监督钟**（观察时间戳、命令时间戳、
期限全部用 sim 钟），期限改为 sim 域声明值：
- close 预算 = **7.0 sim s**（探针自己的闭合窗口末端 `3 <= t < 7`）；
- release 预算 = **2.0 sim s**（释放命令 ~9.0 到判定采样 ~10.8 的声明窗）；
- max_age 同域 = 2.0 sim s（同一步内评估，age ≈ 0.02）。
**模块 `retainer_supervision.py` 零语义改动**（它只做时间差运算，钟域由集成方盖章）；
仅在其文档串加一行"钟域由集成方声明"。
不改：世界、几何、控制器、契约判决逻辑、任何 bench 阈值、既有反例配置。

## 4. 预计如何反证这个修复
1. **确定性**：`neg`/`single`/`unknown` 的 `CLOSE_TIMEOUT` 必须在**首个超过 sim 7.0 的采样**
   （6.82 之后第一个采样，即 10.82）触发——与主机快慢无关；若某次 run 的拒绝
   时刻随墙钟漂移，修复失败。
2. **正例不回归**：`pos` 必须仍在 6.82 采样进入 `CLOSED`（6.82 < 7.0 ⇒ 几何先于期限），
   全生命周期 `OPEN_VERIFIED`。
3. **relblk 翻案**：释放被卡的 run 必须呈现**卡住特征**而非超时：
   `authorized_ever=True`（合法授权）、终态 `TRANSPORTING`（不得 `OPEN_VERIFIED`）、
   release 决策 `reason_code=RELEASE_NOT_AT_TARGET`、`matched=True`、bench `FAIL`。
   若 relblk 再报 `CLOSE_TIMEOUT`，修复失败。
