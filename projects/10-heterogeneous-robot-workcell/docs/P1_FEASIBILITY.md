# P1 共同世界可行性检查点

日期：2026-09-20。结论：候选 A 的部分组件可用，**共同世界技术门未通过**。

## 候选与理由

先验证 MuJoCo 3.3.6 作为唯一物理世界：本机人形资产与 MNN 策略已有相容运行证据。
Gazebo 路线需重新验证人形跨引擎行为，当前不同时开发两条路线。
ROS 3.14 和物理 3.12 分进程，并不意味着两个物理世界；ROS 侧不能独立模拟或改写货物状态。
此为 P1 初选，不是最终架构通过；没有启动完整车间。

  模型的目录**，实测 **80 文件 / 34.9 MB**（此前估算"数 MB"，实测是 34.9 MB，已更正）。

  这不是排版问题：qpos 顺序跟着声明顺序走，插在前面会把上游 `home` 关键帧的 9 个值错位到
  payload 的 freejoint 上，实测**零件开始时躺在世界原点的地板上**。

### C：车载接驳

滚筒仅已解决驱动表面接触的最小问题。下一步需车体支撑、保持机构、间隙与偏航、对接互锁。
源端→车载→接收端每次须完整转移和停止，故意错位时必须拒绝，不靠货物瞬移。
当前滚筒实验初试失败为相邻滚筒重叠；修正半径后运动恢复。后续根据实测速度增加运行时长并加强第三段包含判据，原失败均保留。

**侦察与第一轮实测已完成（`reports/p1-c-deck-02`，判决 `INCOMPLETE`）。**

- **口径纠正**：原来三次滚筒实验用的是程序里的**占位方块**（`.12 x .15 x .02`、0.3 kg），**不是 V1 真托盘**；真托盘底面宽 0.460 m 而旧台滚柱只有 0.440 m ⇒ 那个 `COMPONENT_PASS`从未适用于真托盘。现在滚柱长度**由 `tray_floor` 的 y 半宽推导**：0.460 + 2x0.020 = **0.500 m**。
- **几何约束**：提手伸到 ±0.335 m，**超出滚柱端面 0.085 m** ⇒ 甲板上**不能装齐平侧导轨**（会撞提手）。横向约束是**记录量**：对齐实测横漂 2.0 mm。
- **实测窗口**：缝 30 mm 过 / 60 mm 掉落；**台阶 8 mm 卡死**；偏航 3° 横漂 56 mm、8° 漂 150 mm。⇒ 停靠残余偏航要远小于 3°、高度差要远小于 8 mm；**阈值不能比这个机械窗口更宽**。
- **保持挡销未被证明**：抬起后接触 0 个采样、带销与不带销滑移差 0.0000 m ⇒ 这个加速度下**摩擦单独就够**，判据 `NOT_RUN`。**真正该被质疑的是托盘/甲板声明的摩擦 1.0**（要滑动需约 1 g）。
- **完整转移与卸载已跑通（2026-09-22）**：`reports/p1-c-full-03` 判决 **`PASS`（16 PASS / 0 FAIL / 0 NOT_RUN）**，judge `rc=0`。armed 108 run = **58 准入全部 `DONE`** / 50 拒绝；旁路臂证明 **0 个拒绝"开闸后会成功"** ⇒ **声音性与紧性同时成立**；十阶段（含 `UNLOAD`/`RECEIVED`/`PLATFORM_CLEAR`）全部实际执行，`full_C_acceptance` 由探针自行推导为 `CLAIMED`。
- **本轮修掉的 6 个缺陷**：刀片收起位在托盘体内；`aboard` 把辊排横向半长（0.250）当托盘行程向半长（0.065）；**接收台不在被仿真的模型里**（`run_scenario` 缺 `receiver=True`）；`PLATFORM_CLEAR` 只轮询不驱动；judge 的"坐好在甲板上"与 `DONE` 互斥；**甲板行程参照关节坐标而非世界**。
- **仍未做**：重复性（同场景仍只跑一次）、真实 AMR 底盘、**真实机械余量** —— 两排冠在满行程处**恰好相切（间隙 0.0000）**，现在靠控制口径把缝与偏航算进行程补偿掉，**机构几何一处未动**，故 `PASS` 的 `scope_claim` 强制声明"机构实验、非真 AMR 对接"。`Stopper`（正向止挡）**未加**；推杆**退休**（`REQUIRED_PUSH_TRAVEL = −0.0010`）；retention 仅靠摩擦（F1）。

### N：ROS 与同世界轮式导航

先实现限时本机 IPC：有序号、sim timestamp、命令有效期与零/停止回退；不接任意网络指令。
MuJoCo 唯一发布物理状态，ROS 进程输出 /clock、scan、轮式 odom、TF，消费经命令门的速度。
轮式里程计不得直接读取世界真值作定位；扫描由场景射线/传感器产生。
确认隔离域与端口不影响 009，再单车 Nav2 实际到站。先同世界单车，不先跑双车与全矩阵。


**已完成（`P1-N-06`）**：IPC、时钟、scan、轮式里程计与 TF 全部通过，证据 `reports/p1-n-ipc-07/08`。两条结构性保证值得单独说：

- **状态报文里没有位姿字段**（键只有 `gate/range_max/range_min/ranges/schema_version/seq/sim_time/wheel_rate`）⇒ "里程计不读世界真值"由模式决定，不是承诺；
- **只有一个 `/clock` 发布者**，且时间戳是 sim 时间（最大 23.99 s，墙钟纪元约 1.7e9）⇒ 世界时钟只有一个来源。

**`P1-N-07`（PARTIAL）**：整链已通（见上表），控制器把车开到目标点并停稳，但真值到站误差 0.431 m。根因是 **AMCL 位姿沿路径超前真值 0.247 m（中位）、p95 0.303 m**，而航向中位只差 0.013 rad；同一段路上**轮式里程计只有 0.066 m**，即扫描匹配比里程计差 4.7 倍。目标检查器据此在真值 0.431 m 处判成功 —— 所以 N-07 的判据一律用真值量，不采信 nav2 自己的结论。

**仍未做**：重复性（只有一个目标点）、建图（地图是几何先验）、位姿扰动、严格意义的单命令写者（`/cmd_vel` 上仍有三个发布者）。**AMCL 的运动噪声 `alpha1..5` 已按本代身底盘的实测里程计精度标为 0.02**（`reports/p1-n-08-loc-03/04`），**AMR 选型后必须重标**。
底盘是 010 自制的最小差速模型，**不是 AMR 的选型结果**（`P1-ENV-01`：AMR 模型未定），因此不能用来声称任何关于 AMR 悬挂、侧倾或载荷的能力；选型之后 N 的验收要在真模型上重跑。
