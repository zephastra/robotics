# 测试与验收协议

状态：设计草案，未运行。数值阈值须测量、评审后冻结，本文不是已有成功率报告。

## 1. 测试层级

1. 静态：配置/schema、文件路径、依赖边界、时间/坐标约定。
2. core/contract：fake 设备验证账本、资源、幂等、错误分类，不宣称物理成功。
3. 单技能：真实物理人形/机械臂/输送/AMR，记录传感器与接触。
4. 全链：真实订单、连续货物身份与接触交接、独立真值验收。

## 2. P1 四个最小实验

| ID | 实验 | 必需证据 |
| --- | --- | --- |
| PROBE-H | 自由底座人形稳定站立、双手取放轻空盘 | 身体姿态、底座漂移、抓持/支撑接触、托盘位置；无隐藏约束 |
| PROBE-A | 固定臂从桌面抓起并放下一个零件 | 夹爪接触、物体离台、释放后稳定；规划附着不能充当接触 |
| PROBE-C | 固定带→停稳车载带→接收带 | 间隙/高度/偏航、支撑连续性、托盘不掉落、停带响应 |
| PROBE-N | 同一世界 AMR 经 ROS 2 定位/导航到站 | clock/TF、scan/odom、实际轨迹、停靠误差、停止延迟 |

四实验使用同一引擎和兼容的模型/单位，可分开运行。随后共同加载全部角色，验证无命名/时钟冲突及资源可运行。
P1 不要求完整配料订单；但任一核心物理路径失败不能用 fake 替代后宣称技术门通过。
先跑一例测墙钟耗时，再决定小样本重复；不默认占满 GPU/CPU。

## 3. 阈值冻结

P1/P3 测量并写入后续 `config/acceptance.yaml`：

- 托盘尺寸/质量、输送支撑与接驳间隙、可允许高度差/横向差/偏航。
- 导航停靠误差分布；抓取/放置可达与碰撞可行区间。
- 停稳线/角速度、持续时间；命令失效后最大物理停止时间与距离。
- 图像/点云/TF 最大年龄和时间偏差；物体稳定观测时间。
- 物料完整包含于托盘料位、托盘完整包含于接收区的几何标准。
- 最大接触力/速度、身体倾斜、物品脱落与越界判据。
- 每技能预算、订单预算、有限重试、wall watchdog；预算与实测速度匹配。

阈值不能从一次成功反推。先确定机械可行区间，再检查控制误差是否有余量；没余量则改机构/控制或缩小声明范围。
冻结后调试集与验收集分离；参数/资产改变后重新标记版本，不混合汇总。

## 4. V1 固定用例集合

下面是最小规划集。种子、位置、订单与阈值在 P3/P4 落入版本化 manifest；未实现用例为 NOT_RUN。

### 正常 N：全部要求任务成功、物理通过、安全通过

| ID | 场景 |
| --- | --- |
| N01 | 一张标准配料订单，经 AMR1 完成全链 |
| N02 | 同一订单由 AMR2 执行，不能存在硬编码机器人 ID |
| N03 | 两张不同配料订单顺序执行，数量与身份不串单 |
| N04 | 两车同时请求上料站，互斥与有限排队后均完成 |
| N05 | 两车竞争窄通道与接收站，均有进展且不死锁 |
| N06 | 合法范围内改变零件初始位置，重新视觉定位 |
| N07 | 合法停靠扰动，复核对齐后真实转移 |
| N08 | 物料、托盘库存恰好够两张订单，完成后不生成第三份 |

### 故障 F：安全结果与预期行为分别验收，不要求所有故障最终送达

| ID | 注入 | 预期 |
| --- | --- | --- |
| F01 | 零件缺失 | 不发出完整订单，等待/拒绝并记录缺项 |
| F02 | 相机遮挡或过期 | 不盲抓；有界重观测，无法恢复则停止待处理 |
| F03 | 人形未退出共享区 | 机械臂与输送器不能进入危险动作 |
| F04 | 托盘未到位/接收位有货 | 禁止开带或卸载；等待或明确阻塞 |
| F05 | 停靠偏差超过冻结区间 | 禁止交接；有界重对接或待处理 |
| F06 | 托盘交接一半中断 | 双方停带、车辆不驶离；保持未知/转移态，不假记完成 |
| F07 | 路径阻塞/Nav2 失败 | 有界恢复，不能重复发单无限重试 |
| F08 | 接单前电量不足 | 不分配运输；订单保留给合适设备 |
| F09 | 持货中电量不足 | 保持货物归属，执行已验证安全处置；无处置能力则待处理 |
| F10 | 调度器退出/许可心跳丢失 | 本地保护生效，实际运动在冻结上限内停止 |
| F11 | 托盘掉落或错料 | 独立验收拒绝成功，封锁受影响区，不伪造账本修复 |
| F12 | 用户取消 | 分阶段安全停止；接触交接中不能直接撤销支撑/释放资源 |

### 完整性 I：以自动短测试为主，需要物理证据的用物理补足

| ID | 检查 |
| --- | --- |
| I01 | 重复命令/网络重发不重复抓放和扣库存 |
| I02 | 迟到成功回调不能完成新一代任务 |
| I03 | 交接提交前退出进程，账本不能同时声称双方持有或无人持有 |
| I04 | 租约过期但设备未离开，不能重新授予危险区 |
| I05 | 真值/安全评价掉线，顶层 UNKNOWN，不得 PASS |
| I06 | 仿真暂停/时间回退，wall watchdog 有效；恢复前重新授权 |
| I07 | 控制路径不可读取物体真值；依赖与接口审计 |
| I08 | 任一必需子判据 FAIL/UNKNOWN/NOT_RUN，顶层不接受 |

首次验收共 28 类用例；N01/N04/N05/N07 另各加 2 个冻结种子，共 36 个实例。
这是有限场景工程验收，不是统计可靠性证明。所有失败保留；修复后必须报告新版本并重跑受影响用例与回归集。
不在 P1 就跑 36 例。逐层短测通过后才冻结完整矩阵和墙钟预算。

## 5. 独立评价与报告

每 run 记录：run_id、UTC、完整启动参数、源码/config/资产哈希、依赖版本、种子、sim 与 wall 时间、进程退出码。
运行目录应含 manifest、事件、传感器/真值摘要、接触/轨迹、账本最终快照、评价结果；必要时短录像。
控制器读取传感器，独立评价器读取真值；评价不能用控制器自报完成代替物体事实。

分开输出：

- task_outcome：SUCCEEDED / FAILED / NEEDS_ATTENTION / CANCELLED。
- physical_result：PASS / FAIL / UNKNOWN / NOT_APPLICABLE。
- safety_result：PASS / FAIL / UNKNOWN。
- expected_behavior：PASS / FAIL / UNKNOWN。
- evidence_complete：true / false，与缺失清单。

正常全链验收要求任务成功、物理与安全 PASS、证据齐全。
故障验收可接受 NEEDS_ATTENTION，但必须预先定义对应行为、安全 PASS、证据齐全；不能临时把失败改成预期。
安全必需集合包括机器人间/工位碰撞、共享区互斥、交接互锁、载物稳定、停止响应、传感器时效，不能只检查通道占用。
