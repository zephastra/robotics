## 为什么是两个进程

MuJoCo 在工程 `.venv`（Python **3.12.13**），rclpy 是系统解释器（Python **3.14.4**）——
**两者不能同进程**。于是世界状态与速度命令走 loopback UDP，契约集中在 `src/workcell_ipc/`
（纯标准库，两侧都能 import）。这不是妥协，而是本轮要测的东西本身：P1-N 的措辞就是
"限时本机 IPC：有序号、sim timestamp、命令有效期与零/停止回退"。

## 三条结构性保证（不是承诺，是模式决定的）

1. **状态报文没有位姿字段** —— 键只有
   `gate / range_max / range_min / ranges / schema_version / seq / sim_time / wheel_rate`。
   ROS 侧**不可能**把真值灌进里程计，因为它从来收不到真值。真值只记在仿真侧报告里，
   由独立的判据事后比对。
2. **只有一个 `/clock` 发布者**，时间戳是 sim 时间（最大 23.99 s；墙钟纪元约 1.7e9）。
   世界时钟只有一个来源；009 已经量过"多个 `/clock` 发布者"会让 tf2 丢掉整个缓存。
3. **命令门在仿真侧**：`seq` 单调 + `issued_sim_time` + `ttl_s` + `silence_s`，
   任一不满足即拒绝并**按理由计数**。拒绝的数据报不延长租约。静默超过 `silence_s` 回退为零
   —— ROS 进程死掉必须停车，而不是按最后一条命令继续跑。

## 底盘：四个实测版本

`assets/worlds/world_n_probe.xml` 是 010 自制的最小差速模型。**每一次否决都是一个数字**：

| 版本 | 结果 |
| --- | --- |
| 平面约束（slide x/y + hinge yaw，**无竖直自由度**） | 轮子空转 13.7 rad/s 而车体 x = 0.0000 —— 没有竖直自由度，接触法向力为零，摩擦为零。**这会让轮式里程计等于真值**，正好毁掉 N 要测的东西 |
| 两驱动轮 + 两个**球形脚轮** | 打滑 **64%**。接触表说明原因：求解器按**接触刚度**分配载荷而非几何 —— 球-平面各 31.3 N、圆柱-平面各 2.0 N，**89% 的车重压在脚轮上**。把脚轮设为不碰撞后降到 4.8%，是同一个结论的另一面 |
| 四轮全驱 | 直线打滑 2.1% 很好，但转向 **0.842 rad/2 s（指令 2.000）**，偏航里程计误差 0.95 rad —— 四轮固定方向，滑移转向 |
| 两驱动轮 + 两个**无 trail 万向脚轮** | 载荷又变静不定（脚轮 26.8 N、驱动轮 8.5 N），转向 0.655/2.000 —— 无 trail 的脚轮在被拖行方向上不能滚动，只能刮擦 |
| **采用：平面约束 + 竖直自由度（slide x/y/z + hinge yaw）+ 两驱动轮** | 载荷 50/50 落在驱动轮、直线打滑 2.4%、原地转向 92%、里程计误差 1.1% |

**它不是 AMR 的选型结果**（`P1-ENV-01`：AMR 模型未定），所以不能用来声称任何关于悬挂、侧倾或
载荷的能力；选型之后 N 的验收必须在真模型上重跑。它可以翻不了车，这一点在文件头和 `D023` 里明说。

## 过程里我犯的错（全部由机器抓出来）

1. **仿真比墙钟快 45 倍**：24.002 s sim / 0.534 s wall，整个 run 在 ROS 侧还在 `import rclpy`
   时就结束，481 个数据报发给了一个尚未绑定的端口。⇒ 加 `sim.realtime_factor: 1.0`。
2. **run 目录守卫写反了语义**：ROS 侧先建 `reports/<run-id>/`，而仿真侧用 `exist_ok=False`
   ⇒ 仿真拒绝启动并且**一个报告都没写**。守卫改成"不覆盖已有证据"（检查自己的报告文件）。
3. **判据三处错**（`05/06` 的 FAIL 全部来自判据，不是链路）：
   ① "恰好一个发布者"把 DDS 发现期的 0 也算违规 ⇒ 正确的不变量是"**从不超过 1 且出现过 1**"；
   ② 偏航误差按实数相减，没做圆周回绕（5.45 与 -0.98 rad 实际差 0.15，被判成 6.4）；
   ③ 仿真结束时 ROS 侧把"流已结束"误判为 `NO_STATE_FROM_SIM` —— 对只看见沉默的接收方，
      **"跑完了"和"从没启动"是同一种现象**。
4. **判据在缺键时崩溃**（`row['counts']['scan']`）—— 是"判据必须能对合成输入判 FAIL"的测试
   抓到的。判据崩溃绝不能看起来像通过，现在顶层有兜底。

`01`–`06` 六个 run 已归档到 `reports/_invalid/`，README 里逐条写明原因；它们**只移动、不删除**。
