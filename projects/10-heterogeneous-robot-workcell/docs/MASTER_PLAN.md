# 010 总实施方案

版本：规划 v0.2，2026-09-19。所有能力除文档脚手架外均未实现。

## 1. 目标与第一版边界

目标：一张结构化订单驱动人形、机械臂、输送设备和 AMR 在同一物理世界协同完成备料、装载、运输、卸载与核对。
V1 配置：1 人形、1 固定臂、2 台带短输送台的 AMR、1 条上料输送带、1 个带双托盘缓冲位的固定接收输送台；有限室内区域和单窄通道。
V1 使用轻量标准托盘、3 个有隔挡的料位、红/蓝两类简单零件；零件分开摆放，不做杂乱堆叠。
托盘和零件均自由刚体；物理质量、摩擦、尺寸由可行性试验冻结，不凭视觉效果决定。

明确不做：加工机床、复杂装配、运动中抓取、双人形共同抬物、未知环境探索、联合 SLAM、实时 VLA、硬件安全认证。

## 2. 订单流程

示例：`kit_001` 需要 2 个 red_block + 1 个 blue_cylinder，送至 station_b。

1. 检查库存、设备能力、托盘、接收位和电量；缺项明确排队或拒绝。
2. 人形在腰高取盘位抓取空托盘，放到停带上料区。V1 先验证站立操作；短距离空手步行单独验收后接入。
3. 人形退出共享操作区并证明确已清空，固定臂获得区内操作许可。
4. 深度相机定位分开放置的零件；机械臂逐件抓放到托盘独立料位。
5. 检查种类/数量/料位；看不清返回 UNKNOWN，不读取订单反推实际数量。
6. 手臂退出，允许输送带把托盘送到接驳位，前端到位检测使其停止。
7. 空闲 AMR 导航停靠；设备双方握手、停稳和对齐检查通过才启动固定/车载输送机构。
8. 托盘完全进入车载区域且保持装置到位后，原站释放；AMR 运往接收站。
9. 接收站空闲并停靠有效后逆过程卸载；接收台确认托盘/订单，独立评价通过后完成。

首个 episode 从显式初始化开始。V1 不承诺无限持续生产：至少两张订单的有限队列需真实验证；
物资耗尽应明确等待，不能运行中生成或瞬移新托盘。完整空盘回收循环属于 V1.1。

## 3. 共同世界技术门（先做，不押注）

已有经验：人形为 MuJoCo/T800；轮式导航为 ROS 2/Gazebo。不能直接并行启动旧工程解决共享接触。

候选 A：以 MuJoCo 为单一物理世界，为 AMR 的 scan/odom/TF/clock/cmd_vel、相机和机械臂建立 ROS 2 适配。
优点是可复用已验证的人形接口经验；成本是导航/传感器/输送接触适配。不是声称已有现成桥。

候选 B：以 Gazebo 为单一世界，验证 T800 模型、预训练策略及双手控制能否迁移。
优点是贴近既有轮式导航；成本是策略跨引擎、模型与接触适配。不承诺复制权重即可走路。

P1 先查本机资源/版本并选择一个最小候选试验；不同时完整开发两套仿真平台。
通过标准：同世界人形自由底座稳定站立与一次轻托盘操作、机械臂真实抓放、输送接驳、AMR ROS 导航与时钟/TF一致。
若失败，记录明确瓶颈和代价，再决定切候选或请求用户调整范围。不能用固定底座假人形静默降级 V1。
禁止用两个互不碰撞的世界或视觉动画声明通过。跨仿真器物理联合控制不进入 V1。

## 4. 复用原则

- 001/002：导航、地图、任务与电量处理经验。
- 003/005：抓取与手部控制、接触诊断经验。
- 004/006/007：人形运动/双手/视觉的有限已验证部分；实验性能力仍须在新世界验证。
- 008：任务契约、技能监督、预算与失败报告思想；V1 用结构化订单，不要求真实 LLM。
- 009：调度/资源/货物归属经验；不得把当前开发版整套当作可靠基础。

复用前记录来源文件、commit 或逐文件哈希、许可、已知限制、复制日期和本工程测试。
运行不 import 旧工程、不调用旧脚本、不读取旧资产目录、不共用 .venv/数据库。

## 5. 分阶段交付

| 阶段 | 内容 | 退出门 |
| --- | --- | --- |
| P0 | 文档、目录、交接与任务分解 | 文件齐全、状态诚实；无运行声明 |
| P1 | 环境核查、同世界可行性与仿真器决策 | 4 个最小物理实验有报告；关键接口/许可可行 |
| P2 | 纯核心、订单/资源/货物契约、fake 适配 | 冲突、幂等、迟到回调、超时、交接失败测试通过 |
| P3 | 世界、传感器、建图/定位/Nav2及点云接口 | 单车定位导航、坐标/时间/传感器校准和带物停靠测量 |
| P4 | 人形取盘、机械臂装盘、输送器分模块闭环 | 每项有单技能成功与故障证据，未联通前不称订单完成 |
| P5 | 单订单全链物理交接 | 人形→臂→输送→AMR→接收站；完整订单和安全评价通过 |
| P6 | 两车/两订单、站点和道路竞争、有界故障 | 不重复执行、不超容量、不假转移；有限订单推进 |
| P7 | 冻结、验收矩阵、独立复现、演示 | 所有声明对应证据；缺项明确，不擅自 GitHub 发布 |

P1 最小代码可在 `experiments/` 保存，但不能绕过后续契约/验收直接变成产品默认路径。
P3 的 SLAM 是部署建图流程，运行配送以定位为主；动态联合建图不在首版关键路径。
P3 的点云处理先做滤波/桌面分离/简单物体几何，选择 PCL 与实际 ROS/Python/C++版本兼容方案后冻结，P4 接入技能。

## 7. 预算与停止开发条件

阶段任务以一个可验收结果为单位，不估计虚假的必达日期。长测试前测一例耗时，给用户总预算。
同一假设两轮失败无信息增量，先报告/补诊断；不要反复调容差或把整个矩阵当调试器。
V1 完成只按 TEST_AND_ACCEPTANCE，不把“新增 100 个测试”或“最后一次演示成功”当退出门。
已有模块不能满足共同物理世界时，先停在 P1 做范围决策，不能把问题拖到全链集成末尾。
