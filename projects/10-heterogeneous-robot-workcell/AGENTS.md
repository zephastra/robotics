# 010 AI 开发与交接规则

## 目标与权限

- 中文沟通和文档，英文代码标识符。以实际完成订单为目标，不以生成文件数为进度。
- 只在本工程及其明确创建的独立测试目录开发。不得修改、构建、停止 001～009 的任务。
- 用户目前授权建立本工程和详细开发文档；本次 P0 不安装依赖、不下载模型、不启动仿真。
- 后续实施按用户继续开发授权和任务板推进；系统安装、替换环境、付费 API、大模型/大型资源下载、真机、GitHub 推送须明确授权。

## 阅读与单写者

1. 每次先完整阅读 `docs/IMPLEMENTATION_STATUS.md`、`docs/HANDOFF.md`、`docs/TASK_BOARD.md`。
2. 首次接手完整阅读 MASTER_PLAN、ARCHITECTURE、CONTRACTS、TEST_AND_ACCEPTANCE、ROADMAP。
   同时阅读 PRECONDITIONS、DEVELOPMENT_GUIDE、RISKS_AND_SCOPE；其中待决参数不得自行当作已验证事实。
3. 同一源码工作区一次只允许一个 AI 修改。本文不授权自动启动多个子代理。
4. 接手前核实上一位作者已交接或用户明确要求接手；时间戳过期不等于旧进程已停。
5. 未确认所有权时只读，不覆盖别人的未提交改动，不凭旧聊天重建工程。
6. **ACTIVE_TASK 只由手写的 `docs/CLAIMS.md` 记录**（`docs/HANDOFF.md` 是派生的，只镜像它 —— 写进去的领取声明会被下次生成抹掉；从任务板推导出来的叫 `NEXT_ELIGIBLE_TASKS`，是推荐不是领取）；每次只领取一个有验收门的任务，禁止同时换仿真器、控制器和场景。

## 物理与信息边界

- 一个共同物理世界、一个仿真时间源。ROS 通信互通不代表跨仿真器物理交接成立。
- 货物是自由刚体。禁止运行时瞬移、隐藏吸附/weld、关闭碰撞、固定人形底座来冒充通过。
- 输送器接触模型须记录；仅沿接触面施加有界牵引的简化模型必须标注，不能宣称验证了完整滚筒动力学。
- 模型动作规划中的 attach/detach 不等于物理抓取验收。
- 物体真值仅用于初始化、显式故障注入和独立评测，不回流定位、视觉、任务规划。
- 本体状态、理想触觉、相机外参的仿真假设必须明示。不得把理想数据称为真机能力。
- 错误/过期/缺失传感器证据为 UNKNOWN，不能作为空闲、清空或完成证明。
- 不放宽验收阈值，不删除失败例，不用最后一次成功覆盖此前失败。

## 执行、资源与账本

- 任务 accepted 不等于完成；cancel ack 不等于停稳；publish(0) 不等于物理停止。
- 每个执行器链只有一个最终命令写者；规划器只能请求技能，不能直接绕过互锁写电机命令。
- 货物、订单、托盘身份分开；跨设备转移须走事务。交接中断时保持 TRANSFERRING/UNKNOWN 并封锁接驳资源。
- 租约到期不证明设备离开或货物转移完成。持货任务不能直接改归属给另一台车。
- sim 时间用于物理/服务；monotonic wall 时间用于心跳/许可/停止保护；UTC 仅用于命名。
- 仿真冻结可以作为明确标记的保底停止，不得称为实机受控急停；恢复需重新验证授权和状态。

## 修改与测试

- 先失败复现/契约测试，再修改；保留用户改动，使用补丁，不做强制 reset/全局清理。
- 每轮记源码/config/资产指纹；新增代码对应短测试。静态、fake、单技能、物理端到端结果分开。
- 单 worker、低资源验证优先；同一缺陷两次无改善先补诊断，不反复刷长批测。
- 所有运行有 wall deadline、报告 ID、命令、PID/启动标识；不能记录完整环境变量或密钥。
- 只能终止本 run 核验过的进程，禁止 killall/pkill 全局机器人进程。
- 核心判据中的 UNKNOWN/NOT_RUN 不能被子项 PASS 抹掉。顶层 PASS 必须列出完整必需判据集合。
- 仿真预算/阈值/场景变更须有理由、版本与对照；已冻结验收阈值修改需用户确认。

## 每轮交付与主动交接

在剩余额度仍足够整理时交接，不等最后一句话。交接不是承诺在额度耗尽后继续后台工作。
更新当前状态（不追加旧阶段来冒充现状）、HANDOFF 和任务板；实验详细历史放 `docs/history/`。
填写：完成内容、未完成内容、实际命令及退出码、版本/指纹、证据路径、活跃进程、下一步最多三项。
没有实际运行写 NOT_RUN；发现历史结论错误在当前状态更正并保留原报告。
本地 Git 可作为检查点，但只提交本轮核验文件；不能把提交等同于验收，不能未经授权推送。
