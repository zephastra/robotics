# 009：逐阶段交给 AI 的执行指令

使用方式：先交整个交接包，再发送当前阶段的一条消息。不能只发送本文件而不给接口/测试文档。前一阶段未验收时，不要求后面的 AI 跳过它。

下面给的是开发指令，不代表功能已经实现。默认不允许上传 GitHub。

## 第一条：P0 + P1

> 请完整阅读 009_handoff 的全部六份文档。现在仅做 P0 和 P1，不做 Gazebo 整套实现。先核实 WSL、目标目录、现有 ROS/Python/Gazebo 版本，注意旧 002 文档写 Lyrical，不要擅自换 Jazzy。目标为 `/home/ziling/projects/009_multi_robot_fleet`，如果已存在先检查，不能覆盖。将 AGENTS_TEMPLATE.md 的完整正文放根目录 AGENTS.md，将方案放 docs，创建 IMPLEMENTATION_STATUS.md。工程必须完全独立于 001～008。按 domain/validation、持久账本、状态机、分配器、资源预约、假时钟、fake adapter 的顺序实现。核心单元测试不能 import ROS。必须先覆盖幂等提交、过旧代次、取消确认、通道占用时租约到期、出口被占、持货不可转移、重启对账。实现 fake demo 并明确标 fake。交付命令/退出码/报告/未运行项，P1 完成后停下报告，不要开始 UI、人形、LLM 或 GitHub 上传。

### 本阶段要求 AI 给你的证据

- 目标目录、完整 AGENTS 正文已经存在，不再让用户找模板。
- 实测环境，而不是猜测 Python/ROS 版本。
- 无 ROS 的核心测试真正运行过。
- fake demo 中两台车资源申请次序可变化，永远只有一个有效 owner。
- 重启后重复 request 不会重新创建任务。
- 资源过期仍占用和持货故障都有测试，不能只有正常路径。
- P2/P3 等写 NOT_RUN，不写“已经可以导航”。

## 第二条：P2 单车物理基线

> 先读 AGENTS、状态文档、MASTER_PLAN 的 P2 与 TEST_AND_ACCEPTANCE。只实现一台四轮差速机器人在独立 Gazebo 世界里的真实导航。按照 P0 已确认版本写模型、bridge、TF、AMCL、Nav2、Gate；不要更换整个 ROS 环境。地图/世界/资源几何要一致；robot footprint 覆盖轮子。检查 Nav2 实际速度类型与所有 cmd_vel 发布者，确保 Gate 位于速度链最后。先测直行、旋转、停止、障碍停车，再测站点往返。校准实际停止距离与估计误差；同时建立与控制隔离的真值 evaluator。尤其验证 Gate 自身退出时底层是否继续保持旧速度：若是，先实现下游保护，不能略过。所有物理测试使用 gazebo_nav2，无 fake fallback。不要增加第二台或网页。给出实测报告和阈值冻结记录后停下。

### 不能接受的答复

- “模型出现了，所以单车完成。”
- “Nav2 goal accepted，所以导航正常。”
- “publish zero，所以车辆立即停住。”
- “测试失败，把 threshold 放大就过了。”

应看到校准数据、真实到位、实际停车，以及地图/TF/控制链检查。

## 第三条：P3 双车隔离与任务执行

> 仅做 P3。把 P2 已验证的 launch 参数化，支持 r01/r02，共享 map/clock/tf，每车唯一 frame、scan、odom、Nav2 action 和最终 cmd_vel。阅读安装版本 launch 的 TF remap，不要把 namespace 当作 frame 自动前缀。将 Fleet Core 经 ExecuteLeg 接入真实 Nav2 adapter，保留命令代次与取消确认。先跑不争抢通道的分区任务，验证 r01 goal/cancel/force-low 不影响 r02。任务成功必须根据正确站点停车服务条件，logical transfer 明确无实体装卸。完成对应契约和物理测试后汇报；未做 P4 前不能称交通协同完成。

### 本阶段屏幕演示

在同一 Gazebo 世界中两车各做自己的任务。用户对 r01 暂停，r02 继续正常工作。独立 evaluator 检查没有车车碰撞和错误任务完成。

## 第四条：P4 窄道预约与让行

> 仅做 P4，这一阶段是 009 核心。按 CONTRACTS 实现通道、连接段、出口缓冲的原子 bundle 预约。候车位不能挡出口；车辆到保护区外 release 节点且整个 footprint 清空后才释放。所有进入动作必须由实际许可驱动，Nav2 staged goals 加本地 Gate 保证无许可不能跨界，不能仅 UI 显示“预约”。实现 FIFO、公平等待、owner/boot/revision/generation 校验、续期与到期停车；占用或位置未知时 TTL 到期仍封锁。定向执行 N04、N05、F03、F09、F10：交换先后请求、出口占用、通道内失联、仅续期中断。明确记录 Gate 前后速度与阻挡原因。禁止固定 sleep 排车序、关闭碰撞、仅报告两台都到了目标。所有案例分别交付任务、安全和预期行为结果。

### 必须回答的四个问题

1. 谁现在拥有保护区？有什么代次的许可？
2. 为什么另一台不能进？它在哪里等？
3. owner 掉线后，为什么没有错误释放？
4. 如何证明 Nav2 没有绕过调度，而不是“通常不绕过”？

## 第五条：P5 三车、低电、故障接管

> 仅做 P5。通过配置加入 r03，不复制第三份写死节点代码。完善三车分配、能量准入、模拟充电区容量、失败重试和重启对账。按 F04～F14 与 N07/N08 定向测试。重点区分取货前可接管、持货后不能凭空接管；失联不等于停止，旧命令未失效不能重派。通道永久阻塞允许明确 attention，不要求系统穿过障碍完成任务。中央重启保留 SQLite，恢复期间保持保守占用，epoch/revision 重新核对。打印预期故障触发是否实际发生，前置未到不算通过。不要接人形、LLM 或多路口。

### 必须看到的反例

一台车持货后故障，另一台不能突然拿到相同 payload；但不相关任务可以继续。这是正确约束，不是要“修掉”的失败。

## 第六条：P6 可核对展示

> 仅做 P6。已有控制逻辑不变，用实际事件和估计状态实现 localhost 只读网页与 RViz 标记。展示每车任务/电量/位置/状态、保护区 owner/generation/队列、Gate 拒绝原因、故障时间线；显示当前 backend 和 logical payload 限制。网页不能自己播放预设任务动画，不能用 evaluator 真值控制机器人。CLI 仍是提交/取消/故障注入入口。增加日志断开、数据过期、未知资源的显示测试；不能断线后还显示绿色运行正常。截图用于演示但不是验收替代。

## 第七条：P7 完整收尾

> 按 TEST_AND_ACCEPTANCE 冻结配置、资产、代码与 30 基础案例；额外跑 N04/N05/N07/N08 的两个固定 seed，总至少 38 次物理运行。先报告预计耗时和磁盘量，用单 worker 执行。每次保存完整输入和 backend，不隐藏环境开关，不删失败或覆盖失败报告。所有基准对比必须匹配版本/参数，不能用旧环境成功报告代表新代码。任务结果、安全结果、预期故障处理分别统计。另做同一任务集单车/双车性能对照，以及新路径独立构建运行。完成 README、局限、来源许可证、故障排查与最终状态文档。没有满足全部门槛就明确未完成；未经用户再次授权不要提交或推送 GitHub。

## 中断后继续的通用指令

> 继续 009，但先不要运行大批测试。完整读取 AGENTS、IMPLEMENTATION_STATUS 和最近报告，核对当前源码/配置 hash 是否与报告一致，说明当前未测试改动和最近失败。只推进当前阶段下一项；不要重新生成整套工程，不改旧项目，不因为上下文丢失就重装环境。如果状态文档与真实文件冲突，以检查证据为准并修正文档。

## 卡住时的通用指令

> 暂停新功能。只调查最小失败 case，按“任务状态→资源归属→action 状态→Nav2 速度→Gate 后速度→Gazebo 驱动→真实位移”逐层找断点，输出对应时间线。区分等待资源、定位失效、Gate 拒绝、无运动、目标不可达和机器运行太慢。先给证据与一个可证伪的假设，再做一项针对性修改；修改后跑该失败与原通过对照。不要盲改到达容差、增加全部超时、扩大场景或声称已到物理极限。
