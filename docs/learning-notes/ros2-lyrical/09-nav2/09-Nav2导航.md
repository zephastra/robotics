# 09 Nav2 导航：从地图、定位到速度指令

> 状态：Draft
> 适用环境：ROS 2 Lyrical、Nav2、差速移动机器人
> 当前验证范围：本机尚未安装并完成 Lyrical Nav2 端到端导航
> 最后核对：2026-08-31
> 原文：[Nav2 Lyrical 文档](https://docs.nav2.org/lyrical/)、[安装说明](https://docs.nav2.org/lyrical/getting_started/build_and_install/local_installation/)
> 上游许可：Nav2 文档仓库为 Apache-2.0；具体软件包以各自声明为准

Nav2 负责路径规划、路径跟随、恢复行为和任务编排。它不会直接让仿真轮子转动；底盘必须先能正确接收速度指令并发布里程计与 TF。

## 1. 安装和检查

```bash
sudo apt update
sudo apt install ros-lyrical-navigation2 ros-lyrical-nav2-bringup

source /opt/ros/lyrical/setup.bash
ros2 pkg prefix nav2_bringup
```

## 2. 启动前的数据契约

| 项目 | 要求 |
| --- | --- |
| 地图 | 可加载的地图 YAML 和图像文件 |
| 定位 | 固定地图模式通常使用 AMCL |
| TF | `map -> odom -> base_link -> sensor` 连续 |
| 传感器 | `/scan` 或参数文件指定的障碍物数据源 |
| 里程计 | 位姿/速度数据与 `odom -> base_link` TF |
| 控制 | 底盘订阅 Nav2 输出的速度话题 |
| 时间 | 仿真时所有相关节点统一使用 `/clock` |

## 3. AMCL 与 SLAM 的关系

在固定地图导航中，常用 AMCL 加载已有地图并发布 `map -> odom`。但“SLAM 与 Nav2 必须二选一”并不准确：Nav2 也可以在 SLAM 持续建图时导航。两种模式应分别配置，且不能让多个节点同时发布同一 TF。

本篇采用较简单的固定地图 + AMCL 模式。

## 4. 准备参数

不要长期直接使用安装目录中的默认参数。把默认文件复制到项目中，根据机器人修改：

- `robot_base_frame` / `base_frame_id`
- `odom_frame_id`
- 激光话题和传感器坐标系
- footprint 或 robot radius
- 局部与全局 costmap
- 速度、加速度和控制器限制
- `cmd_vel` 话题接口

```bash
cp /opt/ros/lyrical/share/nav2_bringup/params/nav2_params.yaml \
  ~/ros2_ws/src/<project_package>/config/nav2_params.yaml
```

## 5. 启动固定地图导航

将占位路径换成绝对路径：

```bash
ros2 launch nav2_bringup bringup_launch.py \
  map:=/absolute/path/to/amr_map.yaml \
  params_file:=/absolute/path/to/nav2_params.yaml \
  use_sim_time:=true \
  autostart:=true
```

真实机器人通常不使用 Gazebo `/clock`，应把 `use_sim_time` 设为 `false`。

## 6. 在 RViz 中操作

1. 打开 Nav2 对应的 RViz 配置。
2. 使用 `2D Pose Estimate` 给出机器人在地图中的初始位姿。
3. 观察 AMCL 粒子和 TF，确认定位收敛。
4. 使用 `Nav2 Goal` 或当前配置中的目标工具发送目标。
5. 观察全局路径、局部轨迹、代价地图和 `/cmd_vel`。

不同 RViz / Nav2 版本中的工具名称可能不是旧教程里的 `2D Goal Pose`，以当前插件显示为准。

## 7. 分层排查

```bash
# 生命周期节点是否 active
ros2 lifecycle nodes

# TF 是否连续
ros2 run tf2_ros tf2_echo map base_link

# Nav2 是否产生速度指令
ros2 topic echo /cmd_vel

# 控制器实际订阅哪个速度话题
ros2 topic info /cmd_vel
```

若 `/cmd_vel` 有数据但机器人不动，问题通常在话题名称、消息类型、控制器状态或底盘插件，而不是规划器本身。

## 8. 最小验收标准

- 地图加载成功，AMCL 能收敛。
- TF 没有断链或重复发布。
- 发送目标后生成全局路径。
- 控制器持续输出速度指令。
- 底盘执行指令并反馈里程计。
- 遇到障碍物时局部代价地图更新，系统可停车或重规划。
