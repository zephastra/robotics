# 11 视觉与 PLC 工业闭环：项目设计笔记

> 状态：Project Note
> 分类：原创项目架构草案，不属于 ROS 2 官方教程翻译
> 当前验证范围：本目录不包含示例所需节点、模型、PLC 配置或测试数据，无法独立复现
> 最后核对：2026-08-31

本篇记录“视觉检测 → 决策 → OPC UA → PLC → 执行机构”的系统边界和后续需要补齐的交付物。它不宣称某个具体工程已经在本仓库跑通。

## 1. 概念架构

```text
[相机/数据源]
      |
      v
[视觉检测节点] -- 检测结果 Topic --> [决策节点]
                                      |
                                      v
                               [OPC UA 客户端]
                                      |
                                      v
                               [PLC / 仿真 PLC]
                                      |
                                      v
                                  [执行机构]
```

## 2. 建议明确的接口

| 边界 | 至少需要定义的内容 |
| --- | --- |
| 相机到检测节点 | 图像话题、编码、帧率、时间戳和相机标定 |
| 检测节点到决策节点 | 消息 schema、置信度、目标类别、追踪 ID |
| 决策节点到 OPC UA | 状态机、幂等性、确认与超时 |
| OPC UA 到 PLC | NodeId、数据类型、读写权限和安全策略 |
| PLC 到执行机构 | I/O 映射、互锁、故障复位和安全停机 |

## 3. 发布为可复现项目前需要补齐

- 可公开的 ROS 2 包和 launch 文件。
- 相机数据或可替代的测试数据集，以及对应许可。
- 模型文件、推理版本和最小硬件要求。
- OPC UA 服务端配置、节点清单和证书策略。
- PLC 变量表与状态机说明；不能只写“写入 M 区”。
- 仿真或硬件在环测试步骤。
- 故障场景：连接中断、重复检测、误检、PLC 拒绝写入、执行超时。
- 安全边界：视觉系统不能绕过 PLC 的硬件互锁和安全逻辑。

## 4. 为什么删除原来的伪命令

原文引用了 `inspect_node.py`、`camera_info_pub.py`、`tf_broadcaster.py`、`write_m_area.py` 和 `sorting_station`，但这些文件在现有仓库中不存在。保留命令会让读者误以为可以运行，因此本轮审计将其改为接口与交付清单。
