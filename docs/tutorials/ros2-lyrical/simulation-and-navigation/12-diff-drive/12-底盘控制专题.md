# 12 差速底盘控制：Gazebo 插件与 gz_ros2_control

> 状态：Draft
> 适用环境：ROS 2 Lyrical、Gazebo Jetty、`gz_ros2_control` 3.x
> 当前验证范围：已确认本机安装 `gz_ros2_control`，插件库为 `libgz_ros2_control-system.so`；尚未用公开机器人模型完成端到端控制
> 最后核对：2026-08-31
> 原文：[`gz_ros2_control` Lyrical 文档](https://control.ros.org/lyrical/doc/gz_ros2_control/doc/index.html)、[`diff_drive_controller` 文档](https://control.ros.org/lyrical/doc/ros2_controllers/diff_drive_controller/doc/userdoc.html)
> 上游许可：以 `gz_ros2_control`、`ros2_control` 和 `ros2_controllers` 各仓库及文件声明为准

差速底盘要完成的核心转换是：把线速度 `linear.x` 和角速度 `angular.z` 转为左右轮关节速度。Gazebo 内置 DiffDrive 系统与 `gz_ros2_control` 是两条不同实现路线；同一组轮子通常只选其中一条。

> Lyrical 官方搭配 Gazebo Jetty，不是 Harmonic。

## 1. 两种路线

| 路线 | 控制主体 | 适用场景 |
| --- | --- | --- |
| Gazebo DiffDrive 系统 | Gazebo 系统插件直接处理 Twist | 快速仿真验证 |
| `gz_ros2_control` + `diff_drive_controller` | ROS 2 控制器管理关节接口 | 接近实机控制架构、长期项目 |

不要同时让两套插件控制同一组轮子关节。

## 2. 路线 A：Gazebo DiffDrive 系统

SDF 中的最小概念示例：

```xml
<plugin filename="gz-sim-diff-drive-system"
        name="gz::sim::systems::DiffDrive">
  <left_joint>left_wheel_joint</left_joint>
  <right_joint>right_wheel_joint</right_joint>
  <wheel_separation>0.30</wheel_separation>
  <wheel_radius>0.10</wheel_radius>
  <topic>/cmd_vel</topic>
  <odom_topic>/odom</odom_topic>
</plugin>
```

元素名和默认话题可能随 Gazebo 版本变化，应以 Jetty 文档和 `gz topic -l` 为准。若 Gazebo 话题与 ROS 2 话题不同，使用第 07 篇的 YAML 明确映射，不要靠复杂重映射猜测。

验证顺序：

```bash
gz topic -l
ros2 topic list -t
ros2 topic info /cmd_vel
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.3}, angular: {z: 0.0}}" -r 10
```

## 3. 路线 B：gz_ros2_control

安装：

```bash
sudo apt update
sudo apt install \
  ros-lyrical-gz-ros2-control \
  ros-lyrical-gz-ros2-control-demos
```

### 3.1 声明硬件接口

```xml
<ros2_control name="GazeboSimSystem" type="system">
  <hardware>
    <plugin>gz_ros2_control/GazeboSimSystem</plugin>
  </hardware>

  <joint name="left_wheel_joint">
    <command_interface name="velocity"/>
    <state_interface name="position"/>
    <state_interface name="velocity"/>
  </joint>

  <joint name="right_wheel_joint">
    <command_interface name="velocity"/>
    <state_interface name="position"/>
    <state_interface name="velocity"/>
  </joint>
</ros2_control>
```

### 3.2 加载 Gazebo 系统插件

```xml
<gazebo>
  <plugin filename="libgz_ros2_control-system.so"
          name="gz_ros2_control::GazeboSimROS2ControlPlugin">
    <parameters>/absolute/path/to/controllers.yaml</parameters>
  </plugin>
</gazebo>
```

原草稿中的 `filename="gz_ros2_control-system"` 与当前安装库名不一致，已改为官方示例使用的 `libgz_ros2_control-system.so`。

### 3.3 控制器参数

```yaml
controller_manager:
  ros__parameters:
    update_rate: 100

joint_state_broadcaster:
  type: joint_state_broadcaster/JointStateBroadcaster

diff_drive_controller:
  type: diff_drive_controller/DiffDriveController
  ros__parameters:
    left_wheel_names: [left_wheel_joint]
    right_wheel_names: [right_wheel_joint]
    wheel_separation: 0.30
    wheel_radius: 0.10
    publish_rate: 50.0
    odom_frame_id: odom
    base_frame_id: base_link
    enable_odom_tf: true
    use_stamped_vel: false
```

轮距和轮半径必须来自实际模型尺寸。`use_stamped_vel: false` 表示本示例接受 `geometry_msgs/msg/Twist`；若使用 stamped 接口，消息类型和发布命令都要相应修改。

### 3.4 加载和检查控制器

只有在 Gazebo 插件已经创建 controller manager 后，才能加载控制器：

```bash
ros2 control list_hardware_interfaces
ros2 control load_controller --set-state active joint_state_broadcaster
ros2 control load_controller --set-state active diff_drive_controller
ros2 control list_controllers
```

发送测试指令前先确认实际话题：

```bash
ros2 topic list -t | grep cmd_vel
ros2 topic info /diff_drive_controller/cmd_vel

ros2 topic pub /diff_drive_controller/cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.3}, angular: {z: 0.0}}" -r 10
```

## 4. 分层排查

1. 关节名是否与 URDF/SDF 完全一致。
2. command/state interface 是否成功导出。
3. controller manager 是否存在。
4. 两个控制器是否为 `active`。
5. 发布者与订阅者的话题名和消息类型是否一致。
6. 是否有两套插件争抢同一关节。
7. TF 与里程计是否只有一个权威发布者。
