# 03 服务与动作：请求、响应与长任务

> 状态：Source Reviewed
> 适用环境：ROS 2 Lyrical
> 最后核对：2026-08-31
> 原文：[Understanding services](https://docs.ros.org/en/lyrical/Tutorials/Beginner-CLI-Tools/Understanding-ROS2-Services/Understanding-ROS2-Services.html)、[Understanding actions](https://docs.ros.org/en/lyrical/Tutorials/Beginner-CLI-Tools/Understanding-ROS2-Actions/Understanding-ROS2-Actions.html)
> 上游许可：[CC BY 4.0](https://github.com/ros2/ros2_documentation/blob/lyrical/LICENSE)

ROS 2 的常见通信方式包括 Topic、Service 和 Action。Service 使用请求/响应模型；Action 适合耗时、需要反馈或允许取消的任务。

## 1. 三种通信方式

| 需求 | 机制 | 特点 |
| --- | --- | --- |
| 持续发送传感器数据 | Topic | 发布/订阅，可多对多 |
| 发出请求并取得一次响应 | Service | 请求/响应 |
| 执行长任务并获得进度、结果或取消任务 | Action | 目标、反馈、结果 |

Service 的通信模型是请求/响应，但客户端既可以同步调用，也可以异步调用。不能简单地把 Service 等同于“只支持同步”。

## 2. Service 实操

先启动 `turtlesim_node`，再在另一个终端运行：

```bash
ros2 service list
ros2 service list -t
ros2 service type /clear
ros2 service call /clear std_srvs/srv/Empty
```

生成第二只海龟：

```bash
ros2 service call /spawn turtlesim_msgs/srv/Spawn \
  "{x: 2.0, y: 2.0, theta: 0.0, name: 'turtle2'}"
```

Lyrical 环境中的接口包名是 `turtlesim_msgs`，不要照抄旧教程中的 `turtlesim/srv/Spawn`。

## 3. Action 实操

先启动 `turtlesim_node` 和 `turtle_teleop_key`。按 `G`、`B` 等键可触发旋转动作；也可以直接使用 CLI：

```bash
ros2 action list
ros2 action list -t
ros2 action info /turtle1/rotate_absolute

ros2 action send_goal /turtle1/rotate_absolute \
  turtlesim_msgs/action/RotateAbsolute \
  "{theta: 1.57}" --feedback
```

`--feedback` 会显示动作执行过程中的反馈。

## 4. 如何选择

- 连续数据流，例如雷达和相机：Topic。
- 一次请求和一次结果，例如查询状态：Service。
- 导航、机械臂运动等耗时任务：Action。

实际设计还应考虑失败处理、超时、重试、QoS 和任务是否需要取消，不能只按“快或慢”判断。
